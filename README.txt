# Bag-Back Lucky Draw Website

## 1. 프로젝트 개요

**Bag-Back Lucky Draw Website**는 전시 관람객을 대상으로 한 인스타그램 팔로우 연계형 럭키드로우 웹사이트이다.
전시 현장에서 관람객이 QR코드를 통해 사이트에 접속하고, 지정된 인스타그램 계정을 팔로우한 뒤 직원 확인을 거쳐 룰렛을 돌릴 수 있도록 설계하였다.

본 사이트는 Bag-Back 세계관의 캐릭터와 굿즈를 활용해 전시 참여를 유도하고, 관람객이 단순히 전시를 보는 것에서 끝나지 않고 직접 이벤트에 참여할 수 있도록 제작하였다.

---

## 2. 제작 목적

본 프로젝트의 목적은 다음과 같다.

1. 전시 관람객의 참여율을 높이기 위한 인터랙티브 이벤트 제작
2. Bag-Back 인스타그램 계정 및 협업 계정 팔로우 유도
3. 전시 굿즈를 활용한 럭키드로우 시스템 구축
4. 직원이 현장에서 직접 확인 가능한 운영 구조 설계
5. 관람자 화면과 관리자 화면을 하나의 웹사이트 안에서 함께 구현

---

## 3. 주요 기능

### 3.1 관람자용 럭키드로우 화면

관람자는 QR코드를 통해 웹사이트에 접속한 뒤, 럭키드로우에 참여할 수 있다.

관람자 화면의 주요 흐름은 다음과 같다.

1. 사이트 접속
2. 인스타그램 계정 팔로우
3. 인스타그램 아이디 입력
4. 직원 확인
5. 직원 인증코드 입력
6. 룰렛 진행
7. 당첨 결과 확인
8. 직원에게 결과 화면 제시 후 선물 수령

---

### 3.2 인스타그램 팔로우 연계

럭키드로우 참여 전, 관람자는 아래 두 개의 인스타그램 계정을 팔로우해야 한다.

* `@bagbackuniverse_official`
* `@cochelab.official`

사이트 내에는 두 계정으로 이동할 수 있는 버튼을 배치하였다.
관람자가 해당 링크를 열었는지 확인할 수 있도록 링크 클릭 여부를 기록하는 구조를 넣었다.

다만 인스타그램 팔로우 여부를 웹사이트가 자동으로 직접 확인하는 것은 제한이 있기 때문에, 실제 운영에서는 직원이 관람자의 휴대폰 화면을 보고 팔로우 여부를 직접 확인하는 방식으로 설계하였다.

---

### 3.3 직원 인증코드 구조

인스타그램 팔로우 확인은 관리자 페이지에서 원격 승인하는 방식이 아니라, 직원이 현장에서 관람자의 휴대폰을 직접 확인한 뒤 관람자 화면에 인증코드를 입력하는 방식으로 구성하였다.

이 구조를 선택한 이유는 다음과 같다.

* 전시 현장에서 빠르게 확인 가능
* 별도의 복잡한 인스타그램 API 연동 없이 운영 가능
* 직원이 실제 팔로우 화면을 직접 확인할 수 있음
* 관람자와 직원의 대면 운영에 적합함

직원 인증코드가 입력되면 룰렛 페이지로 이동할 수 있다.

---

### 3.4 룰렛 시스템

룰렛은 Bag-Back 굿즈 구성을 기반으로 제작하였다.
관람자가 룰렛 버튼을 누르면 준비된 선물 목록 중 하나가 랜덤으로 당첨된다.

룰렛 항목은 선물 수량과 운영 계획에 맞춰 구성하였으며, 관람자 화면에서는 확률이나 재고 관련 설명이 보이지 않도록 하였다.
관람자는 단순히 이벤트에 참여하고 결과를 확인하는 흐름만 경험하게 된다.

---

### 3.5 중복 참여 방지

한 인스타그램 아이디당 한 번만 참여할 수 있도록 설계하였다.
이미 참여한 아이디로 다시 접속하면 새로운 룰렛 참여가 아니라 기존 결과 화면으로 이동하도록 구성하였다.

현재 버전은 정적 HTML 기반이기 때문에 같은 브라우저 환경 안에서 중복 참여 방지가 작동한다.
실제 전시에서 여러 관람자가 각자 다른 휴대폰으로 접속하는 경우에는 중앙 데이터베이스 연동이 필요하다.

## 4. 캐릭터 구성

메인 화면에는 Bag-Back 세계관의 주요 캐릭터 3명을 배치하였다.

캐릭터 순서는 다음과 같다.

1. **LUNGYI_LUNGYI**
2. **DDAENG**
3. **CHICHI**

각 캐릭터 이미지는 누끼 형태로 배치하여 첫 화면에서 Bag-Back의 시각적 분위기가 바로 드러나도록 구성하였다.

## 6. 관리자 기능

사이트 내에는 직원용 관리자 화면을 함께 구성하였다.
관리자는 같은 사이트에서 직원 관리자 버튼을 눌러 비밀번호를 입력한 뒤 관리자 화면에 접근할 수 있다.

관리자 화면의 주요 기능은 다음과 같다.

### 6.1 당첨 / 수령 내역 확인

관람자가 룰렛을 돌린 후 당첨된 선물과 당첨 코드가 관리자 화면에 기록된다.
직원은 선물 지급 후 해당 항목을 `수령 완료`로 변경할 수 있다.

기록 항목은 다음과 같다.

* 당첨 코드
* 인스타그램 아이디
* 당첨 선물
* 당첨 시간
* 수령 상태

---

### 6.2 남은 선물 현황 확인

관리자 화면에서 전체 선물의 남은 수량을 확인할 수 있다.
실제 굿즈별 재고와 룰렛 세트별 남은 수량을 모두 확인할 수 있도록 구성하였다.

확인 가능한 항목은 다음과 같다.

* 총 참여 인원
* 남은 당첨권 수
* 수령 완료 건수
* 수령 전 건수
* 굿즈별 남은 수량
* 세트별 남은 수량

---

### 6.3 참여자 / 링크 기록 확인

관람자가 인스타그램 계정 링크를 열었는지 확인할 수 있는 기록 페이지를 구성하였다.
이를 통해 직원은 관람자가 팔로우 대상 계정으로 이동했는지 참고할 수 있다.

---

### 6.4 세트 및 확률 관리

관리자 화면에서 각 선물 세트의 수량, 남은 수량, 가중치, 노출 상태를 수정할 수 있다.
이를 통해 현장 운영 중 특정 선물이 빠르게 소진될 경우 관리자가 수량이나 노출 여부를 조정할 수 있다.

## 9. 배포 방식

본 프로젝트는 GitHub Pages를 통해 배포할 수 있도록 제작하였다.
`index.html`과 `assets` 폴더를 GitHub Repository의 루트 경로에 업로드한 뒤, GitHub Pages를 활성화하면 웹사이트 URL이 생성된다.

배포 후 생성되는 URL 예시는 다음과 같다.

```text
https://사용자아이디.github.io/repository-name/
```

전시 현장에서는 해당 URL을 QR코드로 변환하여 관람객이 바로 접속할 수 있도록 한다.

---

## 10. QR코드 운영 방식

QR코드는 GitHub Pages 배포 후 생성된 사이트 URL을 기준으로 제작한다.

운영 방식은 다음과 같다.

1. GitHub Pages로 사이트 배포
2. 배포 URL 복사
3. QR코드 생성 사이트에서 URL 입력
4. QR코드 다운로드
5. 전시장 안내물 또는 굿즈 수령 공간에 배치

관람자는 QR코드를 스캔하여 바로 럭키드로우 사이트에 접속할 수 있다.

## 12. 현재 버전의 한계

현재 버전은 정적 HTML 기반의 시제품이기 때문에, 사용자의 브라우저 저장소를 기준으로 데이터가 저장된다.
따라서 같은 브라우저 안에서는 중복 참여 방지와 재고 차감이 가능하지만, 여러 관람자가 각자의 휴대폰으로 접속하는 실제 전시 환경에서는 데이터가 중앙에서 공유되지 않는다.

즉, 실제 전시 운영에서 다음 기능을 정확하게 관리하려면 서버와 데이터베이스 연동이 필요하다.

* 전체 관람객의 참여 기록 통합 관리
* 모든 기기에서 한 인스타그램 아이디 1회 참여 제한
* 선물 재고 중앙 관리
* 관리자 페이지와 관람자 페이지의 실시간 동기화

정식 운영 버전에서는 Supabase 또는 Firebase와 같은 데이터베이스를 연결하여 중앙 관리형 럭키드로우 시스템으로 확장할 수 있다.

## 14. 프로젝트 의의

이 프로젝트는 단순한 이벤트 페이지가 아니라, 전시 관람 경험을 확장하기 위한 참여형 웹 인터페이스이다.
Bag-Back 캐릭터와 굿즈를 활용해 관람객이 자연스럽게 세계관에 접근하도록 만들고, 인스타그램 팔로우와 럭키드로우를 결합해 전시 홍보와 현장 참여를 동시에 유도하였다.

또한 관람자 화면과 직원 관리자 화면을 하나의 사이트 안에 함께 구성하여, 실제 전시 운영에서 필요한 확인, 추첨, 수령 관리 과정을 하나의 흐름으로 연결하였다.
